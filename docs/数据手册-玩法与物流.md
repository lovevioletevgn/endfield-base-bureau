## 🎯 玩法规则（区域限制 / 开采 / 运输）

上一版这一层是空的——我只收了数值，没收规则。现在补上了，**每条结论都带原文证据**，可以在数据包里逐条复核（`data/rules.json` 的 `evidence` 字段，附表名或文案 ID）。

查：`python tools/ake.py 规则`，或 `python tools/ake.py 规则 无线`。

### 一句话版

| 问题 | 结论 |
|---|---|
| 传送带能建在野外吗？ | **不能。** 明文规定只在集成核心区域内允许建造 |
| 开采基建能建在主基地里吗？ | **进不去**——但不是被区域规则挡住，而是**矿机只能放矿点，矿点在野外** |
| 矿怎么进仓库？ | **无线传输**，两条独立通路（电驱矿机 / 协议储存箱） |
| 气体液体怎么进主基地？ | **只能走管道**，跨区域用暗管；配置层面它们**根本没有传送带接口** |

### 一、集成核心区域是"厂区"，野外不是

这是理解另外三条的**前提**。协议核心周围的划拨工业用地叫**集成核心区域**，它有自己的面积、设备数上限、传送带数上限。仓库存取线、息壤供电桩/中继器只允许放这里（或在区内享受无视距离自动连接）。

> 传送带是一种基础物流设备，作用是在设备间运输各种材料，**只限定在集成核心区域中才可以建设传送带**。
> —— 游戏内教学原文（两条文案互为佐证）

所以整张地图的逻辑是：**野外 = 只有采集点，厂区 = 有传送带**。中间那段路，就是下面两条规则要解决的。

### 二、开采基建：只能放矿点上，矿点在野外

配置表里**没有任何一条**写"矿机不得放置在集成核心区域"。真正的硬限制是：

> 矿机是用来开采矿物的设备，**只能放置在矿点上**。

三台矿机的 `desc` 全都这么写，而矿点（源矿/紫晶矿/蓝铁矿/赤铜矿、惰气/酸气）在文案里一律描述为"**分布在野外**"。主基地里没矿点，所以开采基建自然进不去。**结果与实测一致，但原因不是区域禁令。**

气体/液体开采设备同理——气体收集泵"放置在气体矿点上"，水泵/水驱矿机一样依赖矿点。

> **⚠ 别踩的坑：** `placeDomains` 字段里 `miner_1` 只有 `recommendDomains=['domain_1']`，这是"**推荐**地区"不是"禁止区域"。真正的区域禁令走 `placeDomains`（如 `log_hongs_bus`、`power_diffuser_2`、`xiranite_oven_1` 是 `placeDomains=['domain_2']`）。两个字段别混。

### 三、矿物无线传输：两条独立通路

#### 通路 A — 电驱矿机（`miner_2` / `miner_3`）

> 在**通电**后，电驱矿机会自行运转，并**每隔一段时间**将开采到的矿石**无线传输回仓库**。

- 默认就是「**无线传输模式**」，可切换为「**仓储模式**」（切了就只堆缓存区，必须手动取）
- 配置字段：`FactoryMinerTable.hasDroneMode = true`、`msTransferCD = 10000`（10 秒）

> ⚠️ **矿机的 3 个传送带出料口，实际上"没有用"**（2026-09-22 两度核实，并追问「那这样 4 还用吗，玩家都是用无线传输的」）。
> 配置表里它们确实记在 `ports`（`kind=output`、`medium=传送带`，`z=0` 边），但**两种模式都用不上**：
> 默认「无线传输模式」产物直接回仓库；切「仓储模式」也只是进缓存区、**手动取出**（文案原文：
> 「切换到仓储模式后，会和源石矿机一样不会将矿物送回仓库，**必须从缓存区手动取出**」）。
>
> | 矿机（**版本**） | 产物去向 | 依据 |
> |---|---|---|
> | 电驱 / 二型电驱矿机 | **无线回传仓库**（10 秒一次） | 配置表 `hasDroneMode=true` + 教学文案 |
> | **水驱矿机**（**1.1「新潮起，故渊离」·武陵工业二期**新增） | **同样回仓库** | **2026-09-22 实机确认** + 联网核实 1.1 版本公告；配置表里它**不在矿机表**中、没有该字段 |
> | 便携源石矿机 | 进**缓存区**、**手动收取** | `hasDroneMode=false`、`msTransferCD=0` + 文案 |
>
> 所以「占地平面示意」**不再画那 3 个口** —— 直接在建物上标 **⇡ 无线回传仓库**（水驱/电驱/二型电驱）
> 或 **⇥ 缓存区 · 手动收取**（便携源石矿机），图下写明实情与来源。水驱矿机的**管道进料口**（清水）是真口，照常画。
> 数据在 `mining_power.json → gather[]`：`wireless` / `wirelessSource`（配置表 | 实机确认）/ `msTransferCD` / `wirelessNote`；
> `ports` 仍保留（那是配置表事实），只是不画。
> （⚠️ 顺带一条版本更正：水驱矿机是 **1.1** 新增的，不是 1.5 —— 官方 1.1 公告：「开放武陵工业二期，新增赤铜矿物与水驱矿机采集玩法」。
> 所以"它不在矿机表里"与"版本新增"无关，别拿后者当解释。）

#### 通路 B — 协议储存箱（`storager_1` / `storager_nop_1`）

> 在**无线传输模式**下，**已通电**的协议储存箱可以将其内部存放的物品**远程传输到协议核心仓库**。

- **前提是通电**（供电桩/中继器接入电网）。未通电 = 不能传（"储存箱未开启无法无线传输"）
- 配置字段：`FactoryConst.domainTransportIntervalTime = 3600`、`domain2SpHubId = "map02_lv002_sp_hub_1"`

#### 反例：哪些**不**走无线

| 设备 | 为什么 |
|---|---|
| 便携源石矿机 `miner_1` | `hasDroneMode = false`、`msTransferCD = 0`，且文案写"请记得定期返回…**手动收取**"；产物进缓存区 |

> ⚠️ 2026-09-22 **两次更正**：
> ① **水驱矿机 `miner_4` 也把矿物送回仓库**（实机确认）。它曾被列进这张"不走无线"的表，
> 理由是"配置表里不在矿机表、没有 `hasDroneMode` 字段" —— 但**配置表没有该字段 ≠ 游戏里没有这个行为**，
> 别再拿"字段缺失"当成"功能不存在"。
> ② 它的版本我说错过一次：**水驱矿机是 1.1「新潮起，故渊离」新增的**（官方公告原话「开放武陵工业二期，新增赤铜矿物与水驱矿机采集玩法」），
> **不是 1.5** —— 联网核实过。**"它不在矿机表里"跟版本无关，别瞎归因。**
>
> 结论：三种矿机的 3 个传送带出料口**对玩家没有用途**（默认无线回传 / 仓储模式也只是手动取出），
> 所以占地示意**不画它们**了，改标 ⇡ / ⇥ 徽标。

#### 关键推论

**「无线传输」解决的是"野外 → 仓库"这一段。** 矿一旦到了仓库，在集成核心区域内**仓库与背包是连通的**，仓库取货口可以直接把它送上产线。**所以野外那一段完全不需要传送带/管道。** 这也解释了为什么野外没有传送带却不影响自动化。

### 四、气体液体：只能走管道（比想象中更硬）

曾有一种说法是"气体和液体要通过管道运输"——数据比这更硬：**它们连传送带接口都没有。**

从开采到进厂，全链路建筑的端口**全部** `isPipe = true`：抽出来是管口、运是管道、存是管口、用是管口。

**纯管道设备（无任何传送带接口）：**

| 设备 | 端口 |
|---|---|
| 水泵 `pump_1` / 二型耐酸水泵 `pump_2` | 输出 1 管口 |
| 气体收集泵 `gas_pump_1` | 输出 1 管口（免电） |
| 储气罐 / 储液罐 | 进 1 管口 + 出 1 管口 |
| 气体反应炉 `gas_reactor_1` | 2 进 2 出，全管口 |
| 气体散布机 `vaporizer_1` | 1 进管口，无出 |
| 给水器 / 洒水机 / 废水处理机 | 1 进管口 |
| 暗管入口 ×2 / 暗管出口 ×2 | 1~2 管口 |

**混合设备**（带口 + 管口并存，但**流体那一侧仍然必须走管**）：提纯机、反应池、扩容反应池、液气转化机、固气转化机。

跨区域则用**暗管**——官方文案写得很明确：

> 集成工业已通过**多口暗管**完成了**惰气矿区和集成核心区域的连接**。

暗管最大配对长度 **300 米**（`udPipeConnectMaxLength`），明显大于单条传送带（110）和单条管道（80）——**它就是为跨区域长距离流体运输设计的**。

> **附加限制：** 液体/气体的开采与加工还额外需要「**工业开采许可证**」，只在部分地区可用（`缺少液体开采许可，无法进行液体开采`）。

### 五、把三条串起来

```
矿点（野外）                          集成核心区域（厂区）
─────────────                        ──────────────────
矿机 ──无线传输──▶ 仓库 ─┐
                          ├─ 仓库与背包连通 ──▶ 取货口 ──传送带──▶ 产线
协议储存箱 ──无线传输──▶ 仓库 ─┘

气体收集泵/水泵 ──管道──▶ [暗管 ≤300m] ──管道──▶ 储罐/反应炉 ──▶ 产线
```

**固体走无线，流体走管道。** 这是同一套设计的两半——流体塞不进仓库的"物品"槽位，没有无线通路，只能物理运输。

### 六、跨地区传输（库存 / 超库存）—— 仓库不通，但能跨地区送货

仓库是**分地区**的：现在只有两个地区，四号谷地 `domain_1` 与武陵 `domain_2`，各自的仓库互相独立
（文案原文：`6487171838447479486`「各地区仓库是**互相独立**的」）。但两个仓库之间可以**传东西**。
**粒度是「地区」不是「基地」**：一个地区的几片基地**共享该地区这一个仓库**，不是每个分基地各配一个仓库
（2026-09-22 确认）—— 所以跨地区收发的收货方是「地区仓库」，同地区的基地都能从它取货。

入口在 **协议核心 − 协议管理**（`6213431956619667777`）。两种模式：

| 模式 | 行为 | 解锁条件 |
|---|---|---|
| **库存传输** | 在**起点仓库扣除**物品，等量送到终点仓库 | 起点地区「对应建设等级」 |
| **超库存传输** | **不扣起点库存**，终点直接获得；起点地区能产的**任意一种**物品都能传，且**不消耗仓库库存** | 起点地区「较高建设等级」（ `-4573223422367784963` / `359619165901015695` ） |

三条硬约束（排布器按这个算）：

1. **每批只能传一种物品**，数量上限 = **传输总值 ÷ 单位物品价值**（`-6087880617344615614` / `1845235994830423548`）。
   单位物品价值取 `FactoryItemTable.value`（这份数据已经进 `data/items.json`，字段 `value`）。
2. **传输总值取决于出发地（四号谷地）的建设等级**，且随等级提升而增加 ——
   ⚠️ **每一档具体是多少，配置表里没有**：`DomainDataTable.domainDevelopmentLevel` 每级只有
   `bandwidth / battleBuildingLimit / travelPoleLimit / isMineOutputUp` 四个效果字段，没有传输相关项。
   所以本工具**不瞎编档位数字**，改成让你把界面上看到的「传输总值」填进来，由工具反推数量与速率。
3. **一批要等一个间隔**：`FactoryConst.domainTransportIntervalTime = 3600`（界面文案是「%s 后可传输」，
   另有「当前剩余传输次数」）。间隔决定**供货速率**（个/分）= 每批数量 ÷ (间隔小时数 × 60)
   —— 例如每批 1500 个、1 小时一批 = **25 个/分**，跨地区收货**不是无限供**。
   ⚠️ v73 的实现漏除了 60（把「个/小时」直接标成「/分」，虚高 60 倍，「喂不饱」红字永不触发），v74 修正。
4. **解锁门槛与档位（2026-09-22 联网核实，配置表里没有的都用实机/社区实测补）**：
   - 地区建设 **8 级**解锁跨地区传输（库存传输，只能设一种物品；GameWith 与 game735 精华帖双源；
     smzdm 一处写 11 级，采信多数）；**12 级**解锁超库存传输（各源一致）。
   - **传输总值档位**：谷地 11 级 = **1200**、12 级满级 = **1500**（NGA 两帖 + GameRant 一致；
     1500/小时 ≈ value=1 的物品 25 个/分）。页面输入框示例值已从「如 3000」改「如 1500（谷地 12 级）」。
   - ⚠️ **升 12 级后协议不会自动切换**：11 级时设的「库存传输」会继续扣本地产，要手动改成超库存
     （NGA + smzdm 双源，都是玩家踩过坑的提醒）。
   - 中途取消传输再重设，**计时器重置回 1 小时**（GameRant，单源）。
   - 有 NGA 帖称传输**下线不运作、在线才推进**（单源，待实机确认 —— 若属实，离线挂机不产生跨地区供货）。

另外两条容易漏的：

- **能传的清单** = `FactoryItemTable.transferDomainIds`，**243 件，全部是「两地区通用」**（进 `data/items.json` 的 `domains` 字段）。
  野外采集物（惰气 / 惰性壤晶废液之类）不在清单里 → **传不了**，只能本地开采。
- **集成工业系统同时只在至多两个地区运行**（`-623612193743563597` 所在长文案）：
  地区一＝主线最新解锁的协议核心所在地区，地区二＝除地区一外最近停留的地区，其余地区暂时关停。
  → 所谓「多基地」实际是**两地联动**，不是 8 片基地同时开。

> 🔍 **查这类机制的教训**：传输这套东西在 `FactoryConst` 里只留了一个 `domainTransportIntervalTime`，
> 其余全在 **I18n 文案**里写得清清楚楚。**查跨系统机制要配置表 + I18n 双查**，只看配置表会以为它不存在。

## 📡 物流规则（传送带 / 管道）

### 为什么单独一层

**传送带和管道不是建筑。** 它们不在 `FactoryBuildingTable` 里，而是独立的物流实体，写在 `FactoryGridBeltTable`、`FactoryLiquidPipeTable`、`FactoryGridRouterTable` 等表中。

> 🔍 **踩坑记录**：早期版本用 `Conveyor` / `Belt` / `Pipe` 关键词暴力探测表名，**全部落空**，一度以为这些数据不在配置表里。实际命名用的是 **`Grid`**（传送带体系）与 **`Liquid`**（管道体系）前缀。完整表名清单可以从上游仓库直接取：
> `https://api.github.com/repos/XiaBei-cy/EndfieldData/contents/TableCfg`（共 561 张表）。

### 吞吐速率（本库最有价值的新数据）

直接从 `msPerRound`（走完 1 个物品所需毫秒）换算，**每分钟 = 60000 / msPerRound**：

| 载体 | ID | msPerRound | 速率 | 数据来源 |
|---|---|---|---|---|
| **传送带** | `grid_belt_01` | 2000 | **30 个/分钟**（0.5/秒） | `FactoryGridBeltTable` |
| **管道** | `log_pipe_01` | 500 | **120 个/分钟**（2/秒） | `FactoryLiquidPipeTable`（另有 `volume=1`） |

> 这两个数与社区实测一致（玩家测得传送带 0.5 单位/秒、管道 2 单位/秒）；但本库的数值**直接来自配置表**，不是从攻略站抄的。
> ⚠️ 有站点称 MK1=60 / MK2=120 或 T1=300/T2=600，**与配置表不符**，不要在攻略里引用。

| 管道 | `log_pipe_01` | Pipe | 120 | — |

端口朝向（`0/90/180/270`，相对自身）：分流器/汇流器为 `90/180/270` 三向 + `180`，物流桥/管道桥四向全通，准入口单进单出。

### 连接限制常量（`FactoryConst`）

这些是**排线时真正卡人的数**：

| 常量 | 含义 | 值 |
|---|---|---|
| `singleConveyorLengthLimit` | 单条传送带最大长度 | **110** |
| `singleFluidConveyorLengthLimit` | 单条管道最大长度 | **80** |
| `udPipeConnectMaxLength` | 地下管道最大连接长度 | **300** |
| `pipeAngleLimit` | 管道转角限制 | **30°** |
| `maxBuildingCoverGridHeightDiff` | 建筑覆盖允许最大高差 | **4 格** |
| `levelFluidRouterCountLimit` | 单关卡流体分流器上限 | **128 个** |
| `pillarGenerateMinDistance` | 管道支架自动生成最小间距 | **30** |

阀门限流滑块：传送带 `0~5`（默认 1，步长 6）、管道 `0~10`（默认 1，步长 6）；阀门计数 `1~5000`。

### 暗管（地下管道）

暗管是**正经建筑**（在 `FactoryBuildingTable` 里，不在物流实体表），因为它们要占地、要配对连接。`FactoryUndergroundPipeTable` 是**空表 `{}`**。

**入口 / 出口成对使用**，传输管道中的液体和气体：

| 名称 | ID | 占地 | 接口 | 供电 |
|---|---|---|---|---|
| 暗管入口 | `udpipe_loader_1` | 3×3×5 | 1 进（管道，y=3） | 免电 |
| 多口暗管入口 | `udpipe_loader_2` | 3×5×5 | 2 进 | 免电 |
| 暗管出口 | `udpipe_unloader_1` | 3×3×5 | 1 出（管道，y=3） | 免电 |
| 多口暗管出口 | `udpipe_unloader_2` | 3×5×5 | 2 出 | 免电 |

> 背景设定（来自 `decoDesc`）：武陵天师当年设想过「**息壤管道**」——用息壤粒子承托包裹液体、灵活调控流量流速，但因安全问题没投产。这个设想启发了终末地工程师，才有了暗管设备组。多口暗管入口被水工师傅昵称「**排箫入口**」。

#### 版本接口（`mining_power.json` → `ores`）

游戏更新时**只改数据、不改代码**：

| 字段 | 作用 |
|---|---|
| `schemaVersion` | 数据结构版本（当前 3） |
| `perNodePerMin` | **核心口径**：一个矿点 = 1 台矿机 = 满纯度 20/分 |
| `dataVersion` | = 游戏版本（构建时自动取 `GAME_VERSION`），页面顶部显示 |
| `beds[].pointsTotal` | 该矿种的**矿点总数** |
| `beds[].zones[]` | **按小地图**的点位（`zone` / `levelId` / `points`） |
| `beds[].mapMax` | **每个大地区的最大理论值**（逐区核对的那张表） |
| `beds[].theoreticalMax` | 游戏内「理论最大开采值」，带 `version` |
| `beds[].unaccounted` | 按区求和与理论值的**差额**（有差额就登记，不静默） |
| `beds[].mapMaxConfidence` | 每个大地区那个数是**实测**还是**推算** |
| `versionLog` | 逐版本记「这一版矿点/产量变了什么」 |
| `purityRule.zoneUpgrade` | 纯度与地区建设等级的**分区分级**关系 |

`build.py` 构建时跑**自洽自检**：按区求和 ≠ `zonesSum`、`mapMax` 合计 ≠ 理论值、点数×20 对不上 —— 任一项不成立就当场报错。

## 🧩 蓝图分享码：能从数据里拿到什么

游戏内的**蓝图分享码**（形如 `EF01u289AA6uu0eEAoOU`，部分区服前缀 `EFO01`）是真实系统，但**不要指望从配置表解码**：

从 `FacBlueprintConst` 能确认的**只有约束条件**：

| 项 | 值 |
|---|---|
| 码前缀 | `EF01` / `EFO01` |
| 码字符集 | `AEIOUaeiou0123456789`（**不含小写 l**；易混的 0/O、1/I 是主要误输来源） |
| 蓝图最大范围 | **50 × 50 格** |
| 单蓝图节点上限 | **160** |
| 我的蓝图上限 | 100 |
| 赠送上限 | 100 |
| 分享码有效期 | 259200 秒 = **3 天** |
| 名称 / 描述上限 | 15 / 50 字 |
| 标签上限 | 5 |

> ⚠️ **码本身的编码规则不在配置表内。** 全网也没有公开的解码器 —— 现有的第三方蓝图工具（如 `eddy3721/arknights-endfield-bp-tool`、`XiaHouSheng/t2industry`）都用**自定义格式**，前者靠手动画布、后者靠**截图图像识别**，都无法导入游戏原生码。
> **结论**：蓝图码在本库里只能当**不透明字符串**处理，做不了结构化索引。要拿到"别人怎么摆的"，只能人工录入或走图像识别。

| 武陵 | 副基地（次级核心） | **50×50 = 2500 格** | 16 路（推算） | 中（单来源） | B |

来源：
- **A** = 《明日方舟终末地》四号谷地毕业基建合集（17173，作者 `十六_16`，2026-01-31）："核心面积：70x70，单边最大23个取货口；次级核心面积：40x40，单边最大13取货口"
- **B** = 好游快爆问答「武陵主副基地满级后的占地面积有多大？」（答主 守望·灰烬，2026-03-02，"根据我的实测结果"）：武陵主 80×80 / 副 50×50；谷地主 70×70 / 副 40×40

**边长 ↔ 存取口路数**：`单边路数 = (边长 - 1) ÷ 3 向下取整`（1 个仓库存取口占 3 格宽）。
70 → 23、40 → 13 是实测，与该公式一致；武陵侧的 26 / 16 是按同一条规律**推算**的，没实测过 —— 页面和 CLI 都按"推算"标注。

**协议核心本身占 9×9**，压在建设区里：70×70 实际可建 4819 格，40×40 实际可建 1519 格。
（NGA 上有玩家吐槽"不是 80x80，而是 80x80-9x9，因为协议核心占地方"，与这条对得上。）

### 这一层做不到的

- **没有逐个基地的实测面积** —— 面积数据只到"四号谷地/武陵"这一级，同据点下各基地是否等大没核实。
- **武陵那组只有单一来源**，比四号谷地弱一档，上机后建议自己量一遍。
- **建设区边界的形状** —— 只有边长（正方形）和格数，具体哪块被地形/腐蚀区占掉，量不出来。
- **一个基地能放几个次级核心** —— 受协议容量与管家条目限制，配置表给不出直接答案。
