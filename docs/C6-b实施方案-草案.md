## 三、机制已查清（不再有未知项）

### 3.1 垫子配方（原先以为阻塞，已在库中查到）

数据手册第 435-436 行：
> 因此需要**垫子配方**：故意接 2 条**不接输出**的配方让它永久堵塞，再把要销毁的料**溢流**送进去 → 周期性大清洗。
> 社区做法示例：**芽针饮品 / 锦草饮品这类低成本配方**当垫子。

**精确触发条件**：池内**同时进行的 ≥2 条不同配方全部堵塞** → 自动清空池内**所有**内容物。
**只有 1 种配方堵着，什么都不会发生。**

### 3.2 销毁线是「旁路」，不是「主路」（关键认知）

数据手册第 443-445 行：
> 依据：**多口暗管的输出优先特性** —— 同一设备有多个出口时，物品优先走**负载较轻**的路径。
> 搭法：出口 a 直连主路（进仓库），出口 b 接销毁池 → 主路没满时走 a，主路满了自动溢到 b。
> ⚠️ **销毁线是「旁路」** —— 正常运行时它不参与物流，只在爆仓时才被喂料。

**含义**：排布器**不需要**从副产物机器拉一条常供线到反应池。
只要**把反应池摆在图上、垫子配方接好**，游戏侧自己会溢流。
→ **这大幅降低了布局难度**（不用保证长距离供料线）。

### 3.3 速率上限（重要约束）

- 单池销毁上限约 **30/分**（社区口径，**待游戏内核实**）
- 对照实测：**壤晶 100/分、液化息壤 60/分、赤铜块 50/分** → **一个池子远远不够**

**含义**：C6-b 要按 `ceil(溢流量 / 30)` **自动决定摆几个池子**。

### 3.4 ⚠️ 池子自身是故障点

数据手册第 438-439 行：
> 社区多次报告反应池会因交叉反应判定而**无声卡死**（入料满却不出货），需重新摆放 + 重设输出才恢复。
> **不能把它当绝对可靠的安全阀。**

→ 这条**应该在报告里如实告知博士**，不能在工具里假装「装了池子就万事大吉」。

### 阶段 2：门禁 + 自动补销毁支线 ✅ **已完成（2026-09-25）**

**落地形态**（博士拍板后）：
- 新增纯函数 **`RflowSinkPlan(res)`** —— 按 `RflowAudit` 的必爆项定去路：
  · 电池 → 热能池 `power_station_1`（唯一「销毁即发电」）
  · 其余 → 扩容反应池 `mix_pool_2`，**池数 = `ceil(净溢出 / 30)`**（社区单池口径 30/分）
- 新增 **`RflowSinkGate(res)`** —— 软门禁判定（返回 null = 放行 / 返回字符串 = 拒绝原因）
- 新增 **`RplaceSinks(sinkPlan, size, busyFn)`** —— 从画布右下往左上捡空位摆建筑，**不重叠、不越界**
- `LawRun` 接入：**门禁在布局前**（`res` 拿到就判），**摆位预检在 `Lpush` 前**（放不下就干净拒绝，不留半清空状态）
- 报告区（`RflowAuditHtml`）显示：销毁支线清单 + 垫子配方说明 + ⚠️ 池子会无声卡死 + 成本不豁免口径

**⭐ 博士拍板的两个关键口径**：
| 项 | 决定 |
|---|---|
| 补 sink 深度 | **摆池子 + 垫子 + 连旁路**（完整图纸，博士选） |
| 优先级①（被下游消费） | **接上并连线**到消费机器（博士选） |
| 微量溢出阈值 | **≤5/分 只提醒不拦截**（`RW_SINK_MINOR=5`）—— 实测 47/102 个目标有净溢出，多数是整台取整噪声 |
| 池子粒度 | **按物品各摆**（不合并）—— 壤晶@10 = 壤晶废液×4 + 清水×1 |
| 垫子配方 | **不硬编码 id**（接配方是游戏内设置池子反应，不是摆建筑）→ 只给判定条件与选型原则 |

## 五、三个必须由博士拍板的抉择

### 抉择 1：副产物「先找消费者」还是「一律销毁」？

实测发现这些副产物**都有下游配方**（壤晶废液 9 个 / 污水 8 个 / 沉积酸 11 个 / 砂叶粉末 8 个）。

| 选项 | 做法 | 代价 |
|---|---|---|
| **A. 自动找消费者** | 把副产物当**正常原料**递归展开 | 图**可能爆炸**（副产物的下游又产副产物 → 递归极长），且**凭空多出大量机器** |
| **B. 一律销毁** | 副产物入图 → 直接挂销毁支线 | 结构可控；但**浪费**（壤晶废液本可做别的） |
| **C. 只接「主产线里已有消费者」** | 有现成消费就接，否则销毁 | 折中 |

**我的建议：C**（比原先建议的 B 更好）。
理由：阶段 2 的优先级①已经天然实现 C —— 出图时若已有机器吃它，就接上；没有才走销毁。
**不需要专门做 A 的递归展开**（那是 C6-c 的事）。

### 抉择 2：门禁补不上时怎么办？

| 选项 | 做法 | 后果 |
|---|---|---|
| **硬门禁** | 补不上就整个方案作废 | 严格符合红线；但部分目标可能**从「能排」变「排不出」**（画布塞不下池子 + 垫子线） |
| **软门禁** | 补不上则**拒绝出方案 + 明确报原因** | 同硬门禁，但**博士能知道为什么** |

**我的建议：软门禁**。静默作废会让博士困惑。

### 抉择 3：销毁支线要不要「进优化层」？

规格 §2.2 已定：**用电 / 占地 / 线长全算，不豁免**。
→ 这条**已定，不需再问**。但池子数量会直接影响「用电」评分（`mix_pool_2` = 100 电/个），
   博士需知悉：**装了池子的方案会因此在用电层上变差**，这是**有意为之**（真实成本）。
